# 动态基础功率事件模型：调整与验证

日期：2026-09-28。模型格式：`afc.base.2`。本次只标定空载基础功率，没有执行主趋势或残差网络的优化器更新。

后续增加了可选的同会话空载参考校正与恢复时间重复性检查，详见[空载参考校正](动态基础功率空载参考校正.md)。本文件保留不使用参考时的基线结果。

## 调整结果

从全转速共用的一阶动态修正，调整为“稳态曲线＋启动/制动事件参数＋四阶段波形”。研究版的“负载预测 → 基础功率 → 转速查询：峰值/时间”提供目标转速输入，默认初始稳定转速为0。不需要先提供G代码或机床运动参数，就可以查看单次启动估计。

输出包含功率曲线、预计转速、峰值（制动为谷值）、达峰/谷时间、最终稳态功率、进入稳态时间和极值后的恢复耗时。所有时间均相对观测响应起点。没有真实S指令时间戳，未辨识控制器纯延迟。

## 标定和验证方法

1. 沿用CSV读取规则，保持W、r/min、s的工程单位，不重复缩放。
2. 根据实测转速识别完整启动与制动事件；稳态曲线使用稳定窗口末段的功率代表值。
3. 对功率使用默认21 ms中值滤波提取事件特征；同时保留原始极值误差检查，不能通过平滑掩盖明显峰值异常。
4. 每个事件分为极值前、快速恢复、缓慢接近稳态容差带、带内收敛四个阶段。各阶段保留归一化形状，恢复段采用单调包络，不拟合电气纹波。恢复时间作为波形锚点，查询返回的恢复时间再从输出曲线按相同定义计算。
5. 同档位的重复事件稳健汇总，档位间线性插值。启动与制动独立，不外推。新模型同时保存阶段转速形状，用于加工前的主轴响应估计。
6. 三份文件轮流留出，每折只用另外两份文件拟合参数及波形；被留出文件的功率仅用于评分。全部三份文件最后用于生成候选模型。

“进入稳态”的定义为：进入**最终稳态功率**的±max(5 W, 5%×|Pss|)范围，并保持至少0.5秒。不是相对当前瞬时转速对应的移动基线。未完整观察到恢复的事件标记为右删失，不将文件结束时刻作为恢复时间。

模型附带重复事件的实测最小/最大范围，不是置信区间，也不是未来误差保证；中间档位的范围本身同样由插值获得。

## 真实空载留出结果

使用现有三份`空载数据200C2_*_20260721.csv`，原始文件读取前后SHA-256一致。所有54个完整启动/制动事件参与验证，没有通过删除失败事件获得通过结论。

| 留出文件 | 旧版动态RMSE/W | 新版相同窗口动态RMSE/W | 新版完整过渡RMSE/W | 新版功率稳定后MAE/W |
|---|---:|---:|---:|---:|
| 第1份 | 108.70 | 8.89 | 12.45 | 8.51 |
| 第2份 | 107.49 | 5.24 | 5.47 | 2.28 |
| 第3份 | 107.73 | 7.75 | 9.07 | 4.72 |

“相同窗口”保持旧版按转速划分、排除首个平台前段的时间选择；“完整过渡”额外包含功率仍在恢复的尾段，不能将这两类RMSE混为同一个指标。

| 验收项 | 三折最差值 | 当前开发阈值 | 结果 |
|---|---:|---:|---|
| 峰值/谷值相对误差 | 5.1% | 25% | 通过 |
| 达峰/谷时间误差 | 0.101 s | 0.15 s | 通过 |
| 恢复稳态时间误差 | 2.157 s | 0.5 s | 未通过 |
| 稳态代表功率误差 | 16.1 W | 15 W | 未通过 |

峰值相对误差的分母是该事件功率峰谷差、下限50 W；不是除以峰值本身。稳态代表功率误差与整段MAE也是不同统计量。

峰值低估和制动形状的问题明显改善，但不能宣称整个模型通过验收。三次采集的稳态平台和恢复尾段确实有差异；热状态等未记录因素可能有影响，现有数据不足以确定原因。新候选仍为`calibrated_unvalidated`，不会自动替换已有有效模型，也不允许据此进入正式负载网络训练。

## 接口、边界与兼容性

```python
from project.load_prediction import BasePowerModel, predict_base_event

model = BasePowerModel.load("output/load_prediction/event_v2/base_power_candidate.json")
result = predict_base_event(10000, model)  # 初始稳定转速默认为0
print(result["characteristics"])
print(result["validation_components"])
print(result["observed_ranges"])
```

- 标定档位为3000、4000、5000、6000、7000、8000、9000、9500、10000 r/min。中间转速仅作插值，尚无独立档位验证。
- 制动查询：`predict_base_event(0, model, initial_speed_rpm=6000)`；输出`trough_power_w`，不将制动负值截零。
- 加工后接口仍为`predict_base_from_measured_speed`，只用转速确定事件，不用加工功率拟合基础功率。
- 加工前接口仍为`predict_base_from_commands`，指令到响应暂按零延迟对齐并明确警告；初始状态假定已经稳定。
- 非零转速直接切换、尚未稳定就重新启停、超范围和明显不同升降速设置均不作为有效预测；截断事件保留无效区间。
- `afc.base.1`仍能加载和执行原算法预测。新增事件查询需要重新标定。v2保存的旧动态系数字段仅为旧格式接口兼容占位，不代表辨识结果。

算法在`base_events.py`中，文件契约、旧模型预测与公共入口保留在`base_power.py`中，界面单独调用服务。共用同一事件重建与恢复时间判据，避免查询、曲线和验证各算一套结果，落实KISS、DRY和单一职责。没有加入额外神经模型、控制器厂商模拟或未经数据支持的变速工况，保持YAGNI边界。
