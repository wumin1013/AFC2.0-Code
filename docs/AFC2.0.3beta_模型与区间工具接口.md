# AFC2.0.3beta：统一模型与区间划分工具

本说明对应2026年10月28日确定的接口。模型由AFO通过本地机枢调用；区间划分工具静默处理文件，不加载模型、不提供可视化页面。AFO负责信息录入、模型调用、显示和工艺表归档。

## 三个模型输入

| 文件 | 约定 | 提供方 |
| --- | --- | --- |
| `machining_context.json` | 加工条件：机床、刀具、工件；UTF-8 JSON | AFO根据界面填写内容生成 |
| 原G代码，例如 `O123.nc` | 保留完整程序和物理行，不能重排行或删除空行 | 用户导入AFO |
| 原始工艺文件，例如 `台阶T1.txt` | 保留原始序号、N、ap、ae、F、MRR、s、S、G及原顺序 | 用户导入AFO并保存匹配关系 |

加工条件模板见`data/sample/machining_context.json`。默认机床200C-2、刀具“硬质铝合金三刃立铣刀D10”、直径10 mm、3刃、工件6061铝。刀具名称原文保留。AFO用户不必编辑JSON文本。模型文件和运行参数由机枢管理，不计入用户的三个输入文件。

当前498模型入口接受已有的空白分隔原始工艺导出，表头为`序号 N ap(mm) ae(mm) F(mm/min) MRR(mm3/min) s(mm) S(r/min) G`。其他布局必须先验证对应的NC位置映射。区间工具另外支持带或不带序号的标准工艺CSV。N表示一基NC物理行号，不能用G代码中的N段号替换。

## 模型内容与调用

统一文件为`SpindlePowerPredictionModel_V1.0.pt`，schema为`afc.unified_spindle.1`。它包含：

1. H128/F2/seed42第498轮完整切削推理包的原始字节，包括主趋势模型、路径残差网络、分位输出、归一化参数、六维物理特征及十八维路径特征定义、工况编码、配置、版本及原始元数据。
2. 当前冻结动态基础功率模型的完整JSON字节，包括稳态转速—功率曲线、动态事件参数及原资格状态。没有替换为后续全五轮重拟合候选。
3. 空初始位置记忆快照、独立任务记忆使用规则；初始条件校准和额外区间校准均明确为未建立，不伪造已学习记忆。
4. 默认加工条件、适用范围、组件SHA-256、源证据、组件版本和统一包版本。原研究训练检查点、Adam状态及原始数据在研究目录独立保留。

`.pt`需要兼容的运行组件；不能把文件直接当可执行程序。当前本地机枢Python入口：

```python
from project.load_prediction.unified import UnifiedSpindleModel, predict_files

model = UnifiedSpindleModel.load("SpindlePowerPredictionModel_V1.0.pt", runtime_dir="task_runtime")
predict_files(
    model,
    context_path="machining_context.json",
    nc_path="O123.nc",
    process_path="original_process.txt",
    output_dir="prediction_output",
)
```

命令行等价入口为`python -m project.load_prediction.unified_cli predict --model ... --context ... --nc ... --process ... --output ...`。一个模型可以服务多个任务；各任务使用独立输出目录与记忆快照，预测不回写共用模型。未来基础功率更新用`update-base`生成新包，保留切削组件，旧包不被隐式修改。更新后的基础组件仍需自己的验证。

当前默认返回稳态转速假设下的**研究主轴功率估计**。总范围是切削模型q05—q95范围加基础功率点估计，不包含基础功率不确定性，也未获总功率覆盖率校准资格。动态基础功率参数已封装；完整动态计算还需要明确的时间映射和初始状态。仅凭三个现有文件不能宣称已得到真实动态时间线。模型包内保持这些限制和原验证状态。

## AFO向区间工具交接

模型入口生成一个`prediction.json`作为交接文件，另有`prediction.csv`用于核查原模型网格。`prediction.json`的schema为`afc.spindle_prediction.1`，包含：

- `metadata`：程序名、模型版本、三输入SHA-256、`process_file_sha256`、功率/区间身份、位置映射规则、`process_distance_semantics`。
- `rows`：每个原工艺数据行一项，`source_index`为零基原始行序号；`line`为一基NC物理行；还保留执行实例、段内位置、基础功率、总功率、上下界和`status`。

原工艺点与模型网格之间只在同一NC执行段、同一有效序列内插值。在接触切换处，先沿用同一原工艺单元、同接触状态内已有模型网格点的代表值，并记录`mapping_method`及实际`prediction_segment_mm`。2026年10月29日新增小缺口连接规则：原映射仍缺值时，若两侧原网格有效预测属于同一NC行、执行实例和有效序列，且真实几何跨度严格小于0.05 mm，则线性连接基础功率、切削功率、总功率及上下界，允许跨接触状态。已有有效预测保持不变；不外推、不用补点继续填长缺口，跨度等于或超过0.05 mm时仍保留缺值。详见[预测小缺口连接规则](预测小缺口连接规则.md)。

应用上述规则后仍没有模型位置支持的行保留空功率及不可用状态；不填零。接触工艺行仍缺少有效预测时区间工具报错。重复执行且无法用当前RG坐标唯一表达的程序也报错，不能只凭行数对齐。连接仅用于预测输出，不补实测标签、不修改训练监督或模型权重；每个补点保留两侧锚点、跨度及规则版本。

`process_distance_semantics`必须明确为`cumulative_mm`或`incremental_mm`。当前真实原始工艺TXT使用累计s；工具据此使用累计行程，原s字段原样保存。未声明或无有效物理行程时拒绝用虚构距离生成区间。

## 静默区间工具

```text
区间划分工具.exe --process "原始工艺.txt" --prediction "prediction.json" --output-dir "本任务结果目录"
```

默认优化倍率2.0，沿用已有规则；AFO可用`--optimization-ratio`显式传入0.1—5.0内的值。未传参数时，读取EXE同目录的`prediction.json`，仅在能唯一识别一个原工艺CSV/TXT时自动选择输入；多文件时必须传路径。运行无页面、无弹窗、无控制台窗口。每次处理一次并退出，不驻留监控。

发布版采用onedir：`区间划分工具.exe`必须与`_internal`目录一同放入AFO约定的application子目录。当前仅交付本地候选包，没有自动部署到真实AFO安装目录。

## 两类业务输出

| 文件 | 内容 | AFO工作 |
| --- | --- | --- |
| `processinfo.csv` | 原工艺参数、重算MRR、六态编码、区间编号、位置键、预测总功率及范围、区间均值、理想功率和是否被选入优化区间 | 显示并保存到指定工艺信息文件夹 |
| `sampledata.rg` | 被选中的空载/稳态区间及程序当前刀具的理想功率 | 读取区间划分结果用于显示和后续功能 |

两文件均为UTF-8无BOM。`processinfo.csv`前九列保持`N,S(r/min),ap(mm),ae(mm),F(mm/min),s(mm),MRR(mm3/s),G,state_code`；新增列放在后面。状态0—5依次为空载、切入、稳态、过渡、非稳态、切出。六态划分仍由现有工艺算法计算，预测功率用于功率统计。

理想功率沿用**当前程序/刀具所有有效稳态点的平均预测主轴功率×优化倍率**。它是一个程序/刀具的统一目标，不等于每个区间自己的均值。RG最多保留200个有完整功率的空载/稳态区间，按工艺点数选择最长区间，再按坐标排序。没有稳态时不伪造理想功率，RG仅保留版本头；功率不完整的空载区间跳过并计数。

### RG版本与坐标

首行固定为`AFC_RG_PROCESS_V1`。后续行格式：

```text
程序名;理想功率;起始行.点-结束行.点:区间平均预测功率,...;
```

功率单位W、六位小数。行号为NC物理行号减一，点号为该行原工艺记录从零开始的序号。冒号后为区间预测均值；分号第二项为统一理想功率。这一版使用**工艺点坐标**，与旧RG首行0/1/2所表示的实测采样坐标不同。AFO开发人员必须按新头识别并用`processinfo.csv`的`line_index0/point_index0`接回位置，不能把新文件直接交给旧实测RG解析器并声称兼容。

### 完成确认

另生成机器回执`interval_status.json`，用于确认本次两个业务文件同时有效，不是第三种业务结果。AFO应等待进程退出码0，再核`status=completed`及两个输出SHA-256后接收。退出码2表示输入或契约错误，3表示运行失败。失败保留旧输出，但不得把旧文件当本次成功；同一结果目录不允许并发任务。每个任务使用独立目录。
