# 负载预测训练与前后端统一修改计划

日期：2026-10-09  
状态：待实施  
适用范围：AFC2.0 研究版的数据准备、BiLSTM 实际进给、切削负载训练、预测及网页执行流程。

本次修改保留 BiLSTM 实际进给方案，同步修订负载预测实验方案，使实验文档、网页、命令行和后台采用同一套数据资格检查、九折划分、训练顺序、模型选择及评价规则。目标是在 90 轮实验和配套资料通过检查后，可以直接从网页启动完整训练，并加载训练结果预测新程序。

本文件规定后续实施范围。当前仅形成计划，不代表代码已经接通、实验方案已经修订或模型已经训练。

## 当前阶段与正式训练边界

**目前 90 轮实验尚未完成。本计划对应的是为后续训练做准备的代码与文档修改，不是现在启动真实实验数据的网络训练。** 工艺资料、对齐所需信息及新的动态基础功率标定仍需后续补齐。

| 阶段 | 工作范围 | 完成标志 |
|---|---|---|
| 当前计划阶段 | 明确方法、文件修改范围、接口和验收要求。 | 修改计划可供实施，本阶段不修改业务代码。 |
| 后续代码实施阶段 | 实现前后端连接、数据检查、样本规则、九折编排、全量训练、预测和模型保存加载；同步修订实验文档。 | 软件流程可运行，现有数据可检查，缺项能准确提示。 |
| 实验资料就绪后的正式训练阶段 | 真实 90 轮及各模块所需资料通过检查后，由用户启动正式九折开发、配置选择和全量训练。 | 生成经真实数据训练的模型、验证报告及可追溯的模型版本。 |

**代码开发不等待实验全部完成；正式训练等待实验资料通过检查。** 文中“接通训练”“实现全量训练”等任务，均指现在完善对应软件能力，不代表实施代码时就使用尚未齐备的实验数据训练网络。

代码实施期间可用现有实验文件进行读取、质量检查、对齐诊断和候选样本准备。可用小规模合成数据执行优化、冻结、保存加载和端到端测试，但测试权重须与正式模型隔离，不得登记为正式可用模型，也不能据此报告真实预测精度。当前不使用已有部分实验数据进行 BiLSTM、主趋势或残差网络的真实数据训练。

正式训练资格由后台检查，网页、命令行和桌面入口共用，不能只在前端关闭按钮。正式 BiLSTM 训练需完整开发数据、NC、已知条件、进给标签和质量信息通过检查；正式负载训练还需工艺资料、可靠对齐及适用的已验证基础功率。资料未齐时仍可查看缺项、预览实验分组及准备数据，不生成正式训练成功状态。

| 正式负载方法 | PI-CCNVCM 主趋势、多尺度 TCN–Transformer 路径残差、非神经网络的可靠性门控同位置记忆。 |
| 实验分组 | 按原实验表的九种组合进行九折，每折 80 轮训练、10 轮验证。 |
| 最终训练 | 配置选定后重新初始化，用全部 90 轮训练并冻结模型。 |

## 3 数据清单与资格检查

建立统一的数据清单，覆盖 90 个计划轮次、每轮五类程序，共 450 个有效程序位置。一个位置只能有一份当前有效记录；替换记录通过完整检查后，旧记录标记为已替代，保留来源和版本关系。

建议清单至少包含下列信息，具体字段名在实现中统一：

| 类别 | 信息 |
|---|---|
| 计划身份 | 轮次、组合、程序类别、P0—P5 参数组、数据用途。 |
| 文件身份 | CSV/FXT 路径、采样文件内容哈希、NC 版本、工艺资料版本、替代关系。 |
| 实际来源 | 采集时间、实际采集顺序、批次、刀具使用会话。 |
| 已知加工条件 | 机床和设置版本、材料与刀具规格、装夹及冷却信息、编程 F/S、倍率。 |
| 样本资格 | 数据完整性、报警与刀具状态、对齐质量、工艺资料就绪状态、基础功率验证状态。 |

检查顺序为文件配对、格式与通道、实测内容去重、实验映射、质量检查、工艺对齐、样本资格。文件可读取不等于可训练。未知状态必须保留为未知，不能自动填写为合格。

相同 NC 程序的独立重复采样是实验设计的一部分，不能仅因程序代码相同而禁止跨折。相同实测内容的复制文件不能算作不同实验，也不能进入不同集合。

整轮替换须检查五类程序及组合是否完整匹配，再切换该轮有效版本。正式训练任务使用固定数据快照，运行过程中新增或替换文件不应改变正在训练的数据。

界面显示缺文件、重复来源、待工艺对齐、待质量确认、待标定和可训练等具体状态，并给出对应文件与原因。F/S 的正常实验变化、单纯功率偏高或偏低，不作为自动删除依据。

## 4 样本规则与快移边界

进给模型和负载模型共用数据质量、运动状态、执行连续性及断点识别。它们使用不同的任务掩码，不强求所有模型使用完全相同的样本点。

| 用途 | 允许的样本 |
|---|---|
| BiLSTM 进给监督 | 有效切削运动、位置匹配可靠且具有有效实测进给标签的样本。 |
| PI-CCNVCM 主趋势 | 有效切削中的高置信稳态样本，满足转速稳定、刀具正常、无报警和可靠对齐。 |
| TCN–Transformer 残差 | 全部有效切削样本，包括稳态、进退刀、曲面、斜面、台阶及过渡段。 |
| 同位置记忆更新 | 已完成加工、质量明确通过、位置匹配可靠且属于可确认刀具会话的样本。 |

G0 不产生切削训练标签。G1/G2/G3 只是运动类型，是否实际切削还需结合工艺接触信息；不能把所有非 G0 点直接等同于有材料切削。

在 G0、暂停、无效值、缺失区间和执行实例变化处划分连续段，再构造窗口。训练与预测使用同一套连续段和窗口规则，不跨断点插值，不把两段不连续运动拼在一起。

G0 到切削的边界使用 NC 模态、执行对应和工艺信息共同确定，不按进给大小单独猜测。边界处仍有效的真实入刀动态保留给进给模型和残差模型。短段采用明确的变长或遮罩规则，不能为凑窗口而连接无关段。边界所需的加工前条件不能由待预测加工的实测数据回填。

工艺资料不足时可以检查文件和生成候选运动数据，但不能编造切深、切宽或接触状态后放行正式负载训练。

## 5 九折训练与模型选择

统一实验配置保存原方案的确切轮次映射，尤其保留 R10、R15、R25、R34、R39 等已有特殊安排，不能用简单取模重新生成组合。前端显示、BiLSTM、负载训练和命令行均读取这份配置。

每折留出一种完整组合的 10 轮，其余 80 轮训练。同一有效计划轮次的五类程序及全部窗口保持同折。同一原始采样记录不能因切窗或重新命名被拆到不同集合。

每折按以下顺序执行：

1. 锁定训练与验证清单，检查数据用途、来源重复和轮次完整性。
2. 仅使用训练组拟合预处理参数和数据驱动阈值。
3. 用训练组实测进给训练 BiLSTM，选择权重后冻结。
4. 依据适用且通过验证的基础功率，构造实测切削功率标签。
5. 用训练组高置信稳态数据和实测实际进给训练 PI-CCNVCM，随后冻结。
6. 用冻结主趋势生成残差目标，以全部有效切削段和实测实际进给训练 TCN–Transformer，随后冻结。
7. 在验证组使用该折 BiLSTM 的预测进给进行端到端评价，并按实际采集顺序评价同位置记忆。

主趋势冻结后不因残差训练发生更新；负载损失不反向更新 BiLSTM。验证组的实测进给和功率可以用于评分，不能成为正式预测路径的输入。

主趋势保持正值剪切与刃口系数约束。残差输入继续保持文档定义的六类：归一化主趋势、切深与刀径之比、切宽与刀径之比、进给与参考值之比、曲率与刀径之积、程序段长度与刀径之比；其中进给来源按训练和预测阶段明确区分。

P0—P5 是 F/S 参数组，不应被误认成不同材料或不同机床而遭单工况检查拒绝。固定的机床、刀具、材料等工况信息以明确元数据保存；不凭本实验宣称学习了未变化工况的效应。

验证报告包含 MAE、RMSE、R²、峰值误差、高负载低估率、BiLSTM 进给误差，以及有无记忆的对照。峰值误差和高负载阈值的定义须在实验文档、后台计算与界面说明中完全一致。损失和指标先按轮次及程序类别汇总，再等权平均，避免长外形记录支配结果。

按九折平均结果选择统一配置。九折是模型开发结果，不作为未见程序或未见机床、材料的独立泛化证明。

## 6 全量训练与独立验证

配置确定后，三个网络重新初始化，用全部 90 轮训练并冻结。全量训练的训练轮数等参数由开发阶段确定，不使用独立测试集进行早停、选结构或调整阈值。

对于一套固定候选配置，完整流程包括九次折内训练和一次全量训练；每次包含 BiLSTM、主趋势和残差三个网络训练阶段。每个阶段可以包含多个 epoch。搜索多个候选配置时，任务清单应显示实际增加的训练次数，不把九折与九个 epoch 混用。

同位置记忆不属于第四个神经网络。每个验证折独立冷启动；当前程序先预测、评分，完成后再按规则更新。跨折不复用记忆。补采按真实采集顺序处理，不能用较小的计划轮次号把后来采集的数据放到历史数据之前。

程序版本、参数组、刀具会话和模型版本参与记忆兼容性检查。换刀、异常、缺失或匹配失败时按文档暂停或重置。无法确认历史刀具会话时，应保留冷启动或停用更新状态，不虚构会话连续性。

独立的 15 轮同位置记忆验证和 15 轮实际零件测试不参与网络训练。测试前冻结模型和阈值；测试期间只能按既定规则更新同位置记忆。

## 7 前端与后台接口

后台提供一套共享服务，供网页、命令行和现有桌面入口调用。正式训练和预测不能由前端临时拼接另一条流程。

| 服务操作 | 输入与输出 |
|---|---|
| 读取实验规则 | 返回协议版本、九折清单、阶段顺序、输入定义和指标说明。 |
| 检查与准备数据 | 输入数据清单及读取配置；返回缺项、质量报告、分组和可训练状态。 |
| 创建训练任务 | 输入固定数据快照、候选配置和阶段选择；返回任务编号及实际任务清单。 |
| 查看或取消任务 | 返回状态、当前折、网络阶段、epoch、损失、验证指标及错误原因。 |
| 保存和加载模型 | 校验模型状态、输入定义、依赖版本和适用范围。 |
| 加工前预测 | 输入 NC、工艺信息、已知条件、兼容模型和允许使用的历史记忆；返回进给及功率分解。 |
| 评价与记忆更新 | 输入已完成加工的合格实测记录，先评价，再更新对应历史状态。 |

网页需要支持数据缺项定位、九折清单预览、训练启动与取消、实时损失与指标、模型列表、加载和预测结果查看。任务状态由后台保存，刷新页面可重新连接任务；浏览器关闭不应导致结果被误标记为训练成功。

预测结果分别显示主趋势、路径残差、同位置记忆和切削功率。基础功率可用且兼容时再显示总功率；没有训练权重或依赖不兼容时给出明确状态，不显示随机结果冒充预测。

后台长任务与界面事件处理分离。任务失败或取消保留上一份有效模型；只有训练及保存完整成功的新版本才能成为可用模型。运行日志、清单、报告和模型统一放在项目 output 目录。

## 9 动态基础功率与兼容性

动态基础功率保留接口，本计划不重做其辨识算法。接口应返回标定版本、适用域、时间或会话信息以及验证状态。新空载标定通过验证后再接入正式负载标签准备。

待标定期间允许文件检查、对齐和候选样本准备。未经验证的基础功率不能自动放行负载网络训练；独立 BiLSTM 的资格不应被无关的基础功率状态错误阻塞。

模型包保存实验协议、数据快照、输入定义、预处理、基础功率和网络版本。旧格式应明确迁移或拒绝，不能静默把旧规划进给模型解释为实际进给模型。前端和命令行必须显示相同的兼容性结论。

本次研究版训练改造不改变已发布 EXE 的独立反解流程，不修改 NC 和原始采样内容，也不自动提交、推送或发布。既有未提交修改在实施前核对并保留。

## 10 实施顺序与验收

| 阶段 | 交付内容 | 通过条件 |
|---|---|---|
| 1 文档与协议 | 修订实验方案，建立共享实验配置。 | 原方案轮次映射无遗漏，三个入口读取相同协议。 |
| 2 数据与样本 | 统一清单、替代关系、对齐及边界处理。 | 缺项可定位，重复来源被识别，断点不被拼接。 |
| 3 训练与评价代码 | 实现三网络九折编排、指标及记忆评价，以合成数据验证。 | 折内隔离、冻结顺序及预测进给来源正确。 |
| 4 全量训练与保存代码 | 实现配置选择、全量重训入口和模型版本，以测试权重验证。 | 流程不借用独立测试，保存加载结果一致；不产生正式训练结论。 |
| 5 前后端接通 | 网页任务、状态、取消和预测执行。 | 网页与命令行清单及结果在设定数值容差内一致。 |
| 6 完整验收 | 合成数据流程验证、真实数据准备检查、相关回归。 | 具备资料就绪后直接运行正式训练的能力。 |

优先扩展已有 test_feed_samples.py、test_feed_model.py、test_feed_load_contract.py 和 test_load_prediction.py，覆盖九折确切映射、实测内容去重、G0 边界、连续段、输入来源、网络冻结、实际时序记忆及任务状态。API 与页面交互进行端到端检查。新增测试文件在实施范围中明确列出，遵守项目测试目录约定。

重点验收案例包括：

- 90 个轮次恰好覆盖九折；每折 80/10，同轮窗口不会跨集合。
- 相同 NC 的独立记录允许参加实验；复制实测记录不能伪装为新实验。
- G0 到 G1、切削到快移、暂停、缺失和短切削段均不会产生跨界窗口。
- 验证数据的变化不能改变训练组归一化或训练用阈值。
- 残差训练不改变主趋势权重；负载训练不改变冻结的 BiLSTM。
- 预测入口在无法读取待预测加工实测文件时仍可正常工作。
- 补采事件按真实时间处理，当前或未来数据不能提前进入记忆。
- 任务取消、异常和保存中断不会覆盖上一份有效模型。
- 相同数据快照和配置经网页与命令行得到一致分组、输入定义和指标。
- 动态基础功率未通过验证时，页面和后台均拒绝正式负载训练。

本次代码实施的验收标准是“软件能力就绪、真实资料缺项提示正确”，不以当前就取得完整 90 轮数据、正式训练权重或真实精度指标为完成条件。后续数据通过检查后应可直接使用已完成的训练入口，无需再补写核心训练流程；导入新数据不自动启动训练。

实验资料就绪后的使用流程为：导入资料并检查 → 完成工艺对齐与资格确认 → 用户启动九折开发 → 选择配置 → 全量训练 → 加载模型预测 → 加工完成后评价并按规则更新记忆。
