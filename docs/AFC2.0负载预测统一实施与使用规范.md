### B. AFO 本地机枢与 EXE 的职责

AFO 可以不增加功率预测、工艺映射或区间划分算法。AFO 负责输入选择、发起任务、显示状态、读取结果以及曲线/表格/轨迹联动；本地机枢负责机床与加工组合的模型匹配、缓存、版本校验及调用算法 EXE；EXE 负责解析输入、特征计算、功率与区间预测、六态划分和结果导出。EXE 是本地机枢调用的功能组件，不另复制一套算法。理想功率匹配和 i代码生成继续由现有 AFO 功能承接；本次不授权研究模型直接生成或下发机床控制指令。

目标部署位置为 `afomilling/application`。运行时应自带兼容依赖，不要求 AFO 开发人员或最终用户安装 Python/Conda。PyInstaller 一目录包中的 `_internal` 等依赖须完整交付，不能只复制裸 EXE。算法版本、模型格式版本、模型内容版本与输出 schema 版本分别记录。

当前发布入口为 Tk GUI，尚无已验证的无人值守 CLI/任务协议。研究版 TrainingService 的接口及 `/api/v1/` 能力不能直接等同于发布 EXE 接口。近期优先实现一次调用完成一个文件任务；是否再增加常驻 HTTP 服务由实际延迟与并发需要决定。

### C. 同目录输入与自动处理需求

目标是 AFO 或本地机枢将 G代码、工艺信息及任务描述放入同一任务目录，调用 EXE 后自动生成区间与结果，无需用户再次点选或保存。可把 EXE 所在目录用作兼容默认输入目录；正式接口应显式传入任务目录和输出目录，路径不依赖启动时的工作目录。

当前自动查找 `SampleData.csv` + `SampleData.txt` 属于实测采样入口，不能冒称已经支持独立 G代码+工艺 TXT 的全自动无试切流程。现有工艺自动匹配和界面选择能力可复用，但须补齐以下任务契约：

- 输入至少指定 G代码路径、工艺路径、机床ID、程序内容哈希、工艺内容哈希、工艺绑定版本和任务ID；模型由本地机枢匹配，AFO用户不用选模型文件。
- 近期一个刀具/工件组合仍记录刀具直径、刃数、材料及工件材料/牌号，未知项明确为空。新增字段只作记录，不激活旧模型未训练分支。
- 同名内容变化视为新版本；改名但内容相同可复用绑定。多组文件时不能随意选第一份，必须由任务描述指定。输入未写完、哈希不符、编码/列缺失或映射不一致时输出明确错误。
- 明确区分 `segment`、`predict` 和二者组合的任务能力。纯工艺划分不应因缺少实测功率或适用预测模型而被误判为成功预测；不满足预测条件时返回该部分不可用原因。
- 预测不在线训练、不释放反馈、不修改原输入或已发布模型。相同任务ID及相同输入/模型版本可复用；同ID不同内容应拒绝。结果写入临时位置，全部完成并校验后再提交完成标志，失败不冒充旧结果。

字段、精确生成条件和源码行号见[本轮输入输出审计](D:/ResearchLocal/AFC2.0/initial498_adoption_and_afo_contract_20261027_v1/engineering_audit/afo_exe_contract_audit_20261027.md)。对接时至少保留以下区别：

- `intervals.csv`的 `start_idx/end_idx` 是零基闭区间；六态编码0空载、1切入、2稳态、3过渡、4非稳态、5切出。历史六行1—6格式不能混读。
- 工艺`N`是一基物理行号，内部`line_no_raw`零基；`point_labels`显示标签中的点序号加1，而`.rg`使用零基采样行点，禁止直接互换。
- 只有 `path_is_physical=true` 时，`s/path_start/path_end` 才可解释为物理mm；代理路径须明确标记。当前置信类型为 `rule_margin`，空的class/boundary confidence不是统计概率。

- `ProcessInfo.csv`当前字段为 `N,S(r/min),ap(mm),ae(mm),F(mm/min),s(mm),MRR(mm3/s),G,state_code`，输出为UTF-8 BOM；现有格式先保兼容。它的F可能是指令进给，不能与`point_labels.csv`中的`F_program`混同。新JSON使用UTF-8，CSV编码在schema中显式声明。

AFO 应读取结构化文件作为数据源，图片只用于预览。不得由 AFO 从图中反推数值、重新进行六态判别或重新计算模型结果。双方对齐后冻结字段、单位、编码和缺失值语义；新增版本不得静默改变旧文件含义。

建议统一为以下任务输出，**统一任务协议尚未实现，文件名待与 AFO 开发人员确认**；其中 `prediction.csv` 复用研究服务已有能力，不重复开发算法：

### E. 单 .pt 的实际边界

**完整切削推理包已经存在；集成基础功率、切削模型、记忆快照、校准和适用域的统一单 .pt 尚未完成，发布 EXE 也尚未接入498模型。** 研究服务当前依赖 model_id 和多个组件/路径。

后续单个活动组合对外可交付一个完整 .pt，内部至少包含动态基础功率模型、498完整切削模型、位置/程序工艺记忆快照、已验证校准或明确无校准标志、输入与特征定义、适用域、各模块版本/哈希、来源和兼容性要求。统一保存/加载/转换后应能脱离 ResearchLocal 研究目录执行预测；纯封装不需重训九折。原始数据与训练检查点继续独立保留。

.pt 是模型数据包，不是无需运行组件的程序。EXE 仍需兼容模型代码、PyTorch/NumPy及必要原生依赖。不同组合允许引用经过验证且覆盖该组合的通用模型；基础功率组件可按机床复用版本。新刀具个体建立会话并重置/核验相关记忆，不默认从零训练整套网络。没有合格匹配应返回待适配。

现有总功率口径为切削区间加基础功率点估计，`cutting_component_only_base_estimate_added`；未传播基础功率不确定性，不能据此宣称总主轴功率区间达到同样的覆盖率。基础功率资格不齐时，保留切削结果并明确总功率不可用；请求完整动态总功率时还须通过完整时间映射和初始状态检查。已有steady_precutting模式在真实基础资格、切前稳定和恒转速条件合格时可输出steady_total_power_estimate，不强行要求完整动态时间映射，其结果须保持稳态估计身份。

独立BiLSTM资格检查不依赖基础功率。负载训练还要求可靠工艺接触、实测对齐和适用于 `measured_speed_labels` 的基础功率模型/报告哈希及适用域，单凭 `validated=true` 或事件查询成功不能放行。

## 3. 输入、路径和样本

### 3.1 四种进给及39维BiLSTM输入

`F_program`是NC编程进给，`F_cmd`是控制器指令进给，`F_actual`是实测实际进给，`F_actual_hat`是BiLSTM加工前预测；单位均为mm/min。inc仅作可选对照。负载训练使用 `measured_actual_feed`，正式预测及九折端到端验证使用 `bilstm_actual_feed`。

BiLSTM实际学习39维NC特征，顺序由 `FEED_FEATURE_COLUMNS` 固定：

| 维数 | 列名组 | 单位 |
|---|---|---|
| 4 | `motion_g0/g1/g2/g3` | one-hot |
| 6 | `x/y/z_mm`、`end_x/y/z_mm` | mm |
| 5 | `arc_i/j/k_mm`、`arc_radius_mm`、`arc_sweep_rad` | mm、rad |
| 4 | `feed_program_mm_min`、`feed_override`、`block_length_mm`、`segment_fraction` | mm/min、1、mm、1 |
| 3 | `direction_x/y/z` | 单位切向 |
| 3 | `entry_angle_rad`、`exit_angle_rad`、`curvature_per_mm` | rad、rad、mm⁻¹ |
| 2 | `has_previous_block`、`has_next_block` | 0/1 |
| 6 | `previous/next_block_length_mm`、`previous/next_feed_program_mm_min`、`previous/next_curvature_per_mm` | mm、mm/min、mm⁻¹ |
| 6 | `previous/next_direction_x/y/z` | 单位切向 |

物理行号、执行实例、序列号、程序ID、轮次和行程位置用于对齐/分组/追溯，不进入学习特征。机床和设置版本、倍率、加工模式及空间间距参与进给模型兼容校验；不能据此声称已学习材料或机床的独立影响。

实际进给标签优先采用明确实际进给通道，其次采用实际XYZ速度模；经过同步和差分验证后才可用实际XYZ位置差分乘60。指令位置不能充当实际进给标签。缺失、重复访问、暂停和匹配冲突不跨越插值。

空间间距默认0.5 mm，每NC段按不超过该间距等分，保留段端点。直线段长为端点距离，曲率0；圆弧/螺旋段长为 `sqrt((r*theta)^2+dz^2)`，曲率为 `r/(r^2+(dz/theta)^2)`。当前支持固定刀轴XYZ/G17，不声称任意五轴几何。相邻直线拐角由BiLSTM的夹角/邻段特征表示；六维残差的曲率列不会凭空补成圆角。训练和预测复用同一NC网格，不混用旧速度规划样条曲率。

### 3.2 有效样本和窗口

G0、暂停、无效/缺失区间及执行连续性变化形成断点。G1/G2/G3还需工艺接触确认，不能直接等同切削。BiLSTM使用可靠匹配的有效切削运动标签；主趋势使用其中高置信稳态和稳定转速样本；残差使用全部有效切削，包括真实入刀及过渡动态。

BiLSTM核心窗口256点、前后各64点上下文，核心损失不重复；短段使用变长/遮罩。残差窗口256点。窗口在连续段内生成，不连接不相关短段；预测边界只来自加工前可知的NC和工艺，不能用待加工实测数据补齐。

### 3.3 主趋势六物理量与六路径量

物理列固定为 `[ap_mm, ae_mm, feed_input_mm_min, spindle_rpm, diameter_mm, teeth]`。切深/切宽来自工艺，D/z来自明确刀具描述；当前已验证恒定主轴切削入口以NC指令S为物理输入，实测S用于基础扣除和稳定性审核。切削主轴变速而缺少已验证前馈转速时拒绝完整预测。

\[
MRR=a_pa_eF_{in}/60,\quad v_c=\pi DS/60000,\quad f_z=F_{in}/(zS),
\]
\[
L_{eq}=za_p\arccos(1-2a_e/D)/(2\pi),\qquad
P_{phy}=K_sMRR/1000+K_ev_cL_{eq}.
\]

`Ks`单位N/mm²，`Ke`单位N/mm，功率W。系数通过Softplus保持正值，无切削接触时输出0。参考 `vc0=1 m/s`、`fz0=0.1 mm/tooth`、`F0=2000 mm/min` 固定并版本化。

残差只学习六类无量纲输入：

\[
[(P_{phy}-\mu_{train})/\sigma_{train},\ a_p/D,\ a_e/D,\ F_{in}/F_0,\ |\kappa|D,\ell_{block}/D].
\]

主趋势物理量、BiLSTM39维和残差6维是不同输入契约。主趋势冻结后再构造残差标签，负载梯度不回传BiLSTM。默认主系数MLP为2→32→32→2，路径为32通道、kernel3、dilation1/2/4的TCN及2层4头Transformer；这些是可运行默认值，正式配置由开发结果选择。

## 4. 工况、低维适配和风险区间

五分支规范名为 `machine/tool/workpiece/clamping/cooling`，读取时允许material作为workpiece别名。输入为机床功率/转矩/驱动/刚度和测量描述，刀具材料/涂层/角度/悬伸/连接，工件材料族/牌号/硬度/状态，装夹位置/刚度和冷却方式/流量等。具体白名单见 `condition.BRANCH_FIELDS`。版本、材料来源、程序/刀具/机床ID保存作追溯，不作为学习编号。

连续量只按训练组中心/尺度处理，分类量用训练词表，缺失采用训练中心加缺失mask。分支效应减去同网络的参考描述输出，使参考倍率精确1、路径偏置0。单水平分支冻结；默认关闭交互。完全共变的因素只报告组合效应，独立因素解释需要匹配外部实验。固定工况90轮不能证明跨机床/材料效应。

新工况四参数为 `ks_scale=exp(Delta_s)`、`ke_scale=exp(Delta_e)`、`residual_scale=exp(Delta_r)`、`residual_bias_w=Delta_b`。实际进给、共享网络和编码器保持冻结，记忆冷启动为0。先用稳态数据拟合剪切/刃口倍率，再固定主趋势并重新计算路径输入，拟合残差倍率和偏置。两步均检查归一化设计矩阵的秩及条件数（默认上限3000），使用按记录等权的Huber损失；不足或不可辨识时拒绝校准。拟合资料和独立适配验证不得共享实测内容。

路径网络直接训练有序 `q05/q50/q95`，通过中位数及正Softplus上下间隔避免交叉，使用三分位pinball损失。叠加相同主趋势/确定性记忆后得到切削功率三分位。`[q05,q95]`为名义90%模型预测区间，实际覆盖率须用九折及独立测试测量，不能称为95%置信区间。

独立分组区间校准为可选后处理，不是输出三分位的前置条件。它使用独立完整记录的非符合度分组最大值，绑定模型/低维校准/记忆策略版本；资料不足不生成校准声明。校准记录不得来自网络开发或最终测试组。

## 5. 开发、全量训练和评价

每折顺序：固定训练/验证清单 → 训练组预处理 → BiLSTM训练及冻结 → 经验证基础功率扣除标签 → 主趋势训练及冻结 → 残差三分位训练及冻结 → 预测进给端到端验证 → 当前加工评分完成后更新记忆。真实采集顺序未知时，本阶段仅按作者指定编号顺序及同规格多刀合并假设分析；各折冷启动，只由本折已评分验证记录更新，训练记录不注入初始记忆。带替换来源或显式 `memory_eligible=false` 的记录保留评分，但M=0且不得读取、更新编号历史记忆。这不是独立连续刀具会话验证。

损失和指标先记录内计算，再按类别和轮次等权汇总。两组预设负载容量C32/C64按预测进给、关闭记忆的九折平均RMSE、MAE、高负载低估率依次选择；不看独立测试结果。独立BiLSTM完成九折后重新初始化并全90轮训练一次，随后两种负载容量、消融及全量负载复用匹配的进给模型；主趋势和残差选型后各自重新初始化全量训练。各阶段epoch取对应九折最佳epoch中位数向上取整，不从折模型续训、不用全量训练集早停。每完整epoch累积等权梯度后更新一次。九折同时承担早停与选型，只称固定工况开发评价。

| 指标 | 唯一定义 |
|---|---|
| MAE/RMSE/R² | 逐记录计算；常数标签R²为缺失 |
| NRMSE | RMSE除以该训练组冻结的目标尺度 |
| 峰值误差 | `abs(max(predicted q50)-max(target))` |
| P95误差 | 点绝对误差95%分位 |
| 高负载低估 | 标签不低于训练稳态P90时，q50低于标签的比例 |
| 低负载过估 | 标签不高于训练稳态P10时，q50高于标签的比例 |
| 低负载偏差 `low_load_bias_w` | 标签不高于本折训练稳态Q10时，预测减实测的均值，单位W；负值低估，无有效位置则为空并报告点数/记录数 |
| 覆盖率/宽度 | 标签落入[q05,q95]的比例／平均宽度W |
| 区间分数 | 宽度加20倍下界不足量及20倍上界超出量 |
| 高负载上界超出率 | 高负载点标签超过q95的比例 |

另外报告BiLSTM进给MAE/RMSE、具有位置依据时的最低进给及减速起点误差。原方案中的独立记忆验证、未见程序测试及跨工况实验属于后续计划，本阶段尚未实施；不得写成已有15轮验证结果。O1203及其NC、工艺严格保留，不进入本轮准备、训练、统计、评分、记忆或校准。

实测、BiLSTM预测和编程进给的传播对照使用同一冻结负载模型、相同其他输入和冻结/关闭的记忆；实测进给结果明确标为诊断。九折结果不代替未见程序或跨工况独立证据。

## 6. 本地操作与文件

在项目目录的AFC环境启动：

```powershell
conda activate AFC
$env:MKL_THREADING_LAYER = 'SEQUENTIAL'
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python -m project.load_prediction.web_service --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。也可运行 `python scripts/load_prediction.py web --port 8765`。服务仅绑定本机，网页、CLI和桌面复用 `TrainingService`；网页刷新重连任务，任务状态及事件保存在output，浏览器关闭不生成成功状态。服务进程异常退出留下中断状态；取消和失败不覆盖旧模型。

CLI使用JSON请求文件，与HTTP `/api/v1/` 参数相同：

```powershell
python scripts/load_prediction.py protocol
python scripts/load_prediction.py inspect config/inspect_request.json
python scripts/load_prediction.py prepare config/prepare_request.json
python scripts/load_prediction.py preview config/preview_request.json
python scripts/load_prediction.py train config/train_request.json
python scripts/load_prediction.py models
python scripts/load_prediction.py predict config/predict_request.json
python scripts/load_prediction.py evaluate config/evaluate_request.json

```

以上配置文件为用户按实际资料创建的请求，不表示项目已附带完整真实清单。检查请求最小格式为 `{"manifest":"实际数据清单JSON路径"}`；清单schema为 `afc.dataset_manifest.1`。准备负载请求还包含 `base_model_path` 和绑定文件哈希的 `base_validation`。准备成功返回 `snapshot_id`；预览和训练使用该ID，候选配置由 `candidates` 提供。仅训练进给时选 `mode:"feed"` 并调用 `prepare-feed`。

加工前请求包含 `model_id,nc,machine,process,metadata`；metadata提供program_id、feed_override、machining_mode、machine_settings_version、刀具D/z及明确工况。此入口拒绝当前实测进给/功率/报警/振动。输出默认以行程为横轴，显示主趋势、路径残差、记忆、切削功率及三分位；缺完整时间映射或已验证基础功率适用凭据时 `total_power_unavailable`。

模型包 `afc.load.3` 保存正值系数/有序分位权重、五分支编码、输入顺序、参考值、训练归一化、来源及依赖版本；旧包明确拒绝，不静默迁移。output中的snapshots、jobs、runs、models、predictions和calibrations分别保存固定数据、任务状态、开发结果、模型、加工前结果和独立校准。只有完整训练及保存成功的正式模型才进入可用列表。
