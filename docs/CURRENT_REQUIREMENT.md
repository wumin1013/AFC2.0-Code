## 4. SampleData 自动读取

### 4.1 唯一读取位置

发布版只把 EXE 所在目录作为自动读取根目录：

```text
AFC2.0.2alpha/
├─ AFC2.0.2alpha.exe
├─ SampleData.csv

└─ _internal/
```

不得把当前工作目录、源码目录、`data/sample` 或工艺信息文件目录作为发布版的回退数据来源。

### 4.2 文件契约

- 文件名大小写不敏感，但必须分别唯一匹配 `SampleData.csv` 和 `SampleData.txt`。
- 两个文件必须同时存在、非空且可打开才开始解析。
- 同一目录出现仅大小写不同的同名候选时，报“文件名冲突”，不得任意选择。
- 默认实际负载源固定沿用索引 1，即 VGpro 功率列。
- 文件缺失、为空、格式错误或仍被占用时，不得崩溃；必须清空陈旧实测状态并显示明确原因。
- 自动读取失败后仍允许导入工艺信息并完成过程域区间划分，但不伪造实际负载图。
- 发布界面不提供隐藏的手动 SampleData 文件选择回退入口。

## 5. 工艺信息与 SampleData 对齐

### 5.1 当前主方案

当前数据契约区分“物理文件行号”和“G 代码程序段 N 编号”：

- `SampleData.csv` 第 4 列程序行号是 NC 文件的零基物理行索引。
- 工艺信息表独立的 `N` 列当前被解释为一基物理行号，读取后减 1，再与 SampleData 程序行号匹配。
- 工艺信息 G 指令文本中的 `N20`、`N30` 等是程序段编号；绑定原始 NC 文件时用于一致性校验和查找其实际物理行。
- 程序段编号允许跳号，`N20、N30、N50` 不要求连续；每个编号通过原始 NC 文件解析到自己的物理行位置。
- 同一物理行对应多个工艺点或多个采样点时，使用该行内的出现顺序建立点序并映射边界。
- 只要工艺信息中的 N 行号完整有效，就必须优先按 N 对齐，不得退回行程顺序比例映射。
- N 行号只有部分缺失时，先按最后一列 G 代码的连续同指令组继承该组已有物理行号；仍有空缺时再通过绑定 NC 文件匹配完整 G 指令定位。补齐后统一按行号对齐，不得整体退回比例映射。
- 若部分 N 经上述两步仍无法唯一补齐，必须停止采样映射并提示检查数据；不得忽略已有 N 行号后整体按比例猜测。
- 若一个很短的过程区间恰好落在两个实际采样点之间，而当前范围内的总采样点足以覆盖全部区间，则把内部边界确定性地量化到相邻采样切点；状态明确标记“短区间按相邻采样点量化”。若总采样点少于区间数，仍拒绝映射，不伪造采样点。
- SampleData 按程序号变化或程序行号下降切分程序块；若多个程序块同时满足同一匹配条件，必须拒绝猜测并报告歧义。

### 5.2 工艺信息 N 列缺失

当工艺信息独立 `N` 列全部为空且无法通过绑定 NC 文件可靠恢复时：

- 按当前程序、当前刀具的过程行程顺序，将区间边界等比例投影到连续的实际采样点范围；
- 映射只改变区间背景落到哪些实际采样点，不改变过程域六态类别和边界；
- 界面和导出诊断明确标记“按行程顺序比例映射（N列缺失）”，不得伪装为精确行号映射；
- 映射成功后最终图仍只显示实际负载与区间背景，不回退显示程序 MRR。

### 5.3 已确认的导入与保存格式

- 用户实际导入的是 `AfoMilling_origin_trace_*.txt`；`ProcessInfo.csv` 是本程序保存出的结果，也允许重新导入。
- AfoMilling 的 `N` 字段和 ProcessInfo 保存出的 `Nxx` 都表示一基程序物理行号，当前读取时减 1、保存时加 1 的闭环规则正确，不改为程序段跳号语义。
- AfoMilling 表头带“序号”列，布局为 `序号,N,ap,ae,F,MRR,s,S,G`；程序忽略序号并从第 2 列读取 N。
- ProcessInfo 不带“序号”列，布局为 `N,S,ap,ae,F,s,MRR,G[,state_code]`；程序从第 1 列读取 N。
- 解析器先用表头确定布局并跳过表头行，因此两种格式都可确定性导入。
- 为兼容旧数据，完全无表头时可按列数、G 指令起点和字段数值形态推断布局；正式外部接口仍优先保留明确表头，避免歧义。

## 6. 自动区间划分与最终图

导入有效工艺信息后自动执行：

1. 解析工艺信息；
2. 由 `ap × ae × F / 60` 重算过程域 MRR；
3. 执行过程域六态区间划分；
4. 若 SampleData 已成功读取，将过程区间映射到实际采样点；
5. 刷新最终图和区间划分概况。

发布版最终图必须遵守：

- 标题为“实际负载与区间划分”；
- 只绘制实际负载曲线；
- 使用半透明六态背景显示 MRR 划分结果；
- 不绘制“程序 MRR”“预测负载”“基准预测负载”等曲线；
- 不因预测不可用而改变显示内容，因为发布版没有预测流程；
- 实际负载数据不存在时可保留过程域诊断图，但不得把 MRR 冒充实际负载。

## 12. 设计原则

- **KISS**：发布版只有“自动读实际数据—导入工艺—自动划分—显示实际负载与区间—保存”的单一路径。
- **YAGNI**：不实现运行期轮询、新分支、新 rg 格式和任何发布版预测模式。
- **DRY**：复用现有 SampleData 解析、过程域划分和公共区间映射，不复制研究算法。
- **SRP**：发布入口、应用组合、区间映射、构建和验证各自承担单一职责。
- **OCP/DIP**：研究应用和发布应用通过独立组合保留各自能力，发布裁剪不删除研究实现。

## 13. 明确不修改

- 不创建新的 Git 分支；
- 不删除主研究源码中的机理辨识、PIT、SMIF、profile 或既有预测算法；
- 不改变六态区间算法和状态编码；
- 不改变 `SampleData.csv`、`SampleData.txt`、`SampleData.rg` 格式；
- 不增加 SampleData 运行期监控；
- 不改变工艺信息独立 `N` 列现有的一基程序物理行号语义；
- 不自动提交、推送、创建 PR、合并、部署或正式归档。
