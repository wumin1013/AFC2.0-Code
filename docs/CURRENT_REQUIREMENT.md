# 当前需求：AFC2.0.2alpha 发布版反解负载预测与测试界面

## 1. 文档状态

- 更新日期：2026-08-14。
- 产品和 EXE 名称保持 `AFC2.0.2alpha`，只修改发布链路。
- 本文档取代此前“发布版禁止预测”的旧口径；发生冲突时以本文档为准。
- 主研究版保留六态算法、profile、空载模型和既有预测契约；界面按第 14 节完成精简与解耦。
- 本轮不自动提交、推送、创建 PR、部署或正式归档。

## 2. 发布版工作流

发布版保持以下顺序：

1. 启动时优先从 EXE 同目录自动读取文件名逐字符完全匹配的 `SampleData.csv` 和 `SampleData.txt`；错误大小写、增加后缀或改名后的文件不作为 SampleData，完整文件对不可用时才回退实验实测 CSV；
2. 用户导入 AfoMilling 或 ProcessInfo 工艺信息文件；
3. 程序按现有算法完成过程域六态划分及 SampleData 映射；
4. 使用 VGpro 功率和工艺信息中的 `ap/ae/F` 反解全局 `Kc/Ke`；
5. 优先使用 EXE 同目录的 `iipinc.txt` 指令进给计算预测负载；
6. 最终图默认显示实际负载和六态背景，勾选“预测负载”后叠加预测曲线；
7. 保存结果时，`ProcessInfo.csv` 的 F 优先写入按工艺点映射后的指令进给。

SampleData 或工艺信息尚未就绪时显示等待状态。预测失败不得影响既有六态结果、实际负载显示和保存能力。

## 3. 反解模型

- 空载功率固定为 `P_idle = 250 W`，本轮不建立空载模型。
- 参数只保留在当前进程内，不写入配置或 profile。
- 反解实际负载源固定为 SampleData 索引 1，即 VGpro 功率。
- 工艺量继续复用现有逐行中点映射；同一物理行内按点数均匀覆盖采样点。
- 反解 MRR 固定使用工艺信息中的编程进给：`MRR = ap × ae × F_program / 60`。
- 使用所有有效切削锚点，剔除空载点、无效值、无工艺锚点和突变点。
- 按 `P_actual - 250 = Kc × MRR + Ke × ap` 联合拟合非负 `Kc/Ke`。
- 拟合沿用主代码的最少样本、缩放矩阵秩和条件数检查，条件数上限为 `3×10³`；实现不得依赖 SciPy 或 scikit-learn。
- 非负边界解属于合法结果；真实案例出现 `Kc=0` 不视为实现失败。

## 4. iipinc.txt 契约

### 4.1 读取位置

只读取 EXE 同目录、精确文件名为 `iipinc.txt` 的文件，不搜索工艺文件目录、当前工作目录或其他回退目录。程序不轮询或热监控；绘图刷新只检查文件大小和修改时间以复用内存缓存。

### 4.2 行与列

- 每个有效物理行至少 8 列；允许末行实际只有 11 列。
- 第一列与工艺信息 N 列语义相同，是一基物理行号，读取后减 1。
- 第八列为原始指令进给：双行格式转换为 `F_command = column_8 × 0.6 × 10^-4`；单行格式转换为 `F_command = column_8 × 0.6`。
- 同时支持单行和相邻双行格式：若全部非空行都能按前 8 列数值完全一致的相邻两行配对，则自动识别为双行格式并只保留每对第一行；否则自动识别为单行格式并逐行直接使用。
- 允许文件末尾包含 `Total periods <数量>` 汇总行；该数量必须与前面的数据行数一致，汇总行不作为指令点。
- 列数不足、非法/非有限数值、非正整数行号或负指令进给均视为整体结构无效；单行格式允许奇数行，且相邻行无需一致。

### 4.3 映射和回退

- 指令点按零基物理行号分组。
- 每行复用现有中点公式，把该行指令点按点数均匀覆盖到同一行的 SampleData 样本。
- 文件不存在或整体结构无效：全部使用编程进给 `F_program`。
- 文件有效但个别工艺切削行缺失：只对缺失行使用编程进给 `F_program`。
- 右侧预测状态用测试人员可直接理解的文字显示覆盖行数和编程进给回退行数。

## 5. 最终预测与绘图

最终公式固定为：

```text
P_pred = 250 + Kc × (ap × ae × F_command / 60) + Ke × ap
```

- 非切削/空载点显示 `250 W`。
- 实际负载为 NaN 的位置，预测曲线也保留 NaN 断点。
- 默认标题为“实际负载与区间划分”；显示预测曲线时为“实际负载、预测负载与区间划分”。
- 实际负载使用现有青色实线；预测负载使用红色虚线；六态半透明背景保持原分类结果。
- 新增默认未勾选的“预测负载”开关；开关只控制曲线可见性，不阻止后台反解与预测计算。
- F、S、ap、ae 和区间状态现有图形选项保持不变。
- 预测失败时仍绘制实际负载和六态背景，并在只读状态中显示失败原因。

## 6. 界面和状态

发布版右侧区域改为紧凑的“运行结果”，只显示测试人员需要采取行动的信息：

- 处理是否完成，以及生成的区间总数；
- 实际负载是否匹配成功；
- 预测负载是否生成、固定空载 `250 W`、指令进给覆盖和回退数量。

界面不显示 `Kc/Ke`、矩阵秩、条件数、六态分项计数或“采样映射”等学术术语；这些诊断仍保留在运行数据中供程序校验。启动和导入工艺信息时只允许一次最终图刷新，不得先绘制 SampleData 预览再立即覆盖，也不得由多个启动定时器重复调整同一图形。

不恢复机理辨识区域、PIT/SMIF 标签页、profile 选择或预测显示开关。

## 7. ProcessInfo 保存进给

- 只在发布版保存链路中替换 `ProcessInfo.csv` 的 `F(mm/min)`；研究版保持原行为。
- 对每个非合成工艺点，按 N 对应的零基物理行号读取 `iipinc.txt` 指令点，并复用行内中点均匀映射。
- 匹配到的工艺点写入指令进给，`MRR(mm3/s)` 同步按写出的 F 重新计算。
- `iipinc.txt` 缺失、整体无效或个别行未覆盖时，相应工艺点保留原编程进给，不写 0、不留空。
- 保存完成提示必须说明替换点数和回退点数；完全没有可用指令进给时明确说明 F 已保留编程进给。
- `SampleData.rg` 字节级契约不变。

## 8. 内存缓存

- 预测结果缓存键包含 SampleData 文件大小/修改时间和当前内存数组身份、工艺内容、`iipinc.txt` 大小/修改时间及固定空载值。
- iip 解析结果单独按文件大小和修改时间缓存，切换程序、刀具或图形选项不得重复读取约 25 MB 的文件。
- SampleData、工艺内容或 iip 文件签名变化后必须失效并重算。
- 不增加定时轮询、文件监控线程或热重载服务。

## 9. 发布边界

发布包允许并必须包含轻量模块：

```text
project.prediction_support
project.release_prediction
```

发布包仍不得包含：

- `project.app`、`project.pit_model`；
- PIT、SMIF、profile 前向预测入口；
- scikit-learn、SciPy、joblib、threadpoolctl；
- 项目 `.py` 源文件、配置、测试、用户数据或开发机绝对路径。

`SampleData.csv`、`SampleData.txt` 和 `iipinc.txt` 是 EXE 同目录运行输入，不属于发布载荷，不写入 `SHA256SUMS.txt`。

## 10. 构建时运行输入保护

`scripts/build_release.ps1` 替换现有最终发布目录前，必须：

1. 从旧 EXE 目录备份根目录下存在的 `SampleData.csv`、`SampleData.txt`、`iipinc.txt`；
2. 记录每个文件的 SHA-256；
3. 完成候选包验证后替换发布目录；
4. 原样恢复上述运行输入并逐文件复核 SHA-256；
5. 正式归档时排除这些本机运行输入。

构建替换目录时还必须原样保护现有 `SampleData.rg` 与 `ProcessDataPath.txt`，避免重建 EXE 删除用户已经生成的结果和路径状态；这两个运行产物同样不进入正式归档。

发布验证脚本在验证现有最终目录时忽略根目录这三个运行输入，但仍要求所有发布载荷完整纳入校验清单。

## 12. 验收标准

自动验收至少覆盖：

- iip 成对去重、前 8 列校验、一基转零基、进给缩放及行内中点映射；
- 奇数行、列不足、非法数值、不一致、无文件和缺失行回退；
- 合成数据恢复已知 `Kc/Ke`；
- 反解使用编程 F，最终预测使用 iip 指令 F；
- 固定 250 W 空载、NaN 绘图断点和缓存失效；
- 启动和工艺导入不会安排重复图形刷新，发布版右侧只显示三项通俗状态；
- `ProcessInfo.csv` 的 F 和 MRR 使用指令进给，缺失行保留编程进给并显示回退说明；
- 发布图默认只包含“实际负载”，勾选后增加“预测负载”，六态状态掩码不变；
- 发布归档包含两个轻量预测模块而不含研究模块和重依赖；
- `SampleData.rg` 字节级契约不变。

必须在 Conda `AFC` 环境真实执行：

1. `python -m compileall -q src tests`；
2. `python -m unittest discover -s tests -p "test_*.py"`；
3. `python -m pip check`；
4. 两个 PowerShell 脚本语法检查；
5. `git diff --check`；
6. 当前真实 SampleData、iip 和 AfoMilling 工艺文件无窗口复现；
7. `scripts/build_release.ps1 -CleanBuild` 及最终目录发布验证；
8. 核对运行输入构建前后 SHA-256 不变，项目内只保留一份 EXE。

当前真实 iip 验收预期为单行格式，共 641,094 个数据行和指令点，末尾 `Total periods 641094` 与数据行数一致。使用当前指定的实测负载和工艺信息文件时，固定空载反解得到约 `Kc=1.0105、Ke=11.6788`。

- 主窗口只注册“主页面”和“PIT”两个页面，删除 SMIF 与数据分析页面及其后台任务实现。
