# 动态基础功率恢复尾段对比

本轮已按方法调研建议实现并运行两个非神经网络候选。结论：**保留现有事件模型；此前空载事件的时间尺度校正有局部改善，但尚未全面优于基准，也未通过原恢复时间阈值。**

## 方法与实现范围

共同保留事件模型的稳态曲线、峰前波形、峰值和快速回落段，只调整快速回落锚点之后的慢尾段。启动、制动分别拟合，不修改负功率，也不改变原验收阈值。

- `phase_warp`：联合辨识慢恢复时长随转速的平滑规律，用该时长重新映射原事件尾段的时间轴。每个方向三个共享系数，不为每个档位增加独立自由参数。
- `exponential`：在快速回落锚点连续接入 `P=Pss+A exp(-(t-t_fast)/tau(S))`，从训练文件的完整尾段功率联合拟合随转速变化的时间常数。

两种规律都使用归一化转速的二次式，经有界映射得到0.01～30秒的正参数。二次式是参数随转速的变化规律，**不代表二阶动态系统**；指数候选是一个一阶恢复尾段。它们也不同于之前逐事件拟合双指数再取中位数的方案。

采用有边界的稳健最小二乘和固定的轻微曲率惩罚，优化设置没有根据留出成绩搜索。峰值、达峰时间和恢复时间从最终返回曲线计算，曲线与显示参数一致；转速仍来自原训练模板，功率尾段的时间映射不改变转速响应。

## 此前空载参考

参考必须是同记录、同会话、预测前已完成并明确确认空载的前缀。先截取前缀，再识别平台和事件；未来功率、未来无效标记不会影响参考。

稳态偏移沿用已有单参数参考。此前完整事件另外估计恢复时间倍率，每个方向使用最近三个合格事件的对数倍率中位数。尾段不足0.3秒时不更新恢复倍率；倍率超出0.5～2则拒绝该事件，不静默截断。没有合格动态参考时倍率为1。

3000 r/min的实测慢尾段仅约0.06～0.10秒，因此本轮固定首平台参考仅修正功率，不从该事件推断高转速恢复速度。新近平台若不满足已有稳态检查，明确记录拒绝原因并回退到此前合格的平台；不能把切削过程当作空载参考。

参考与候选版本绑定；查询必须提供同记录的未来响应起点 `onset_s`，并严格大于参考 `end_s`。不能将文件间偏移或时间尺度称为已识别的温度。

## 验证设计

三份真实空载CSV只读。每折使用两份文件联合辨识、另一份完整留出；另做三个单文件诊断，单文件拟合不算验证。

分别报告三种输入条件：仅目标转速（54事件）、首个已完成空载参考（后续48事件）、滚动使用此前完整空载事件（相同48事件）。启动及其对应制动使用相同先前参考，不使用该档启动功率预测该档制动。事件基准获得相同的稳态功率参考，避免把更新参考带来的改善错误归因于新尾段。

增加交叉验证：留出测试文件的同时，从其余两份训练文件中移除一个转速档位的事件、功率平台和拟合目标。七个内部档位共42个测试事件；两个边界档位移除后属于训练域之外，共12个事件明确拒绝外推，并单独报告。

峰谷相对误差25%、达峰谷时间0.15秒、恢复时间0.5秒、稳态功率15 W以及稳态带和持续时间定义全部沿用原规则；右删失/无效输出计失败。完整变速RMSE按原1 ms样点评分，报告各折RMSE均值。

三种文件留出条件下，新候选保留了基准的峰谷误差与达峰谷时间表现；最大达峰谷时间误差均为0.097秒。滚动参考的最大稳态偏差为6.817 W，事件基准与两种候选相同。

平滑时长配合滚动参考将最坏恢复误差降低约30%，但0.5秒仍未达标，失败事件由13增至15，RMSE仅从5.456降到5.440 W。不能只根据改善的最大误差宣布新方法胜出。内部档位留出时其最大恢复误差也比事件基准大。指数尾段更差，不建议采用。

所有候选状态均为 `research_candidate_unvalidated`，不会覆盖当前基础模型或自动用于切削标签。三文件被多轮用于方法比较，以上属于探索结果，仍需新增独立记录确认。

## 使用与复现

研究版“负载预测 → 基础功率”增加三个入口：“恢复尾段对比”“恢复候选查询”“加载恢复候选”。耗时比较及查询在后台执行，支持取消；取消或失败保留当前界面中的有效模型。

查询可选择 `phase_warp` 或 `exponential`。`reference_record_index=null` 为无参考查询；使用参考时填写已导入文件的零基序号、`reference_end_s`、`no_load_confirmed=true` 以及同文件时间轴上的未来响应起点 `onset_s`。界面明确显示候选状态、参考来源和时间倍率。真实控制器指令延迟未采集，时间仍相对观测响应起点。

开发接口：`fit_recovery`、`initialize_recovery_reference`、`predict_recovery_event`、`compare_recovery_models`。`RecoveryModel.save/load` 支持JSON保存加载和参数版本校验。

在Conda `AFC`环境运行：

```powershell
python scripts/verification/verify_base_recovery.py '<空载CSV目录>'
```

结果位于 `output/load_prediction/recovery_validation/`：

- `comparison.json`：完整文件留出、参考拒绝原因、交叉档位留出和采用决定。
- `comparison_summary.md`：同口径指标汇总。
- `phase_warp.json`、`exponential.json`：三文件联合标定候选。
- `startup_characteristics.json`：各转速启动的四项主要特征。
- `recovery_holdout.png`：10000 r/min真实留出尾段对比。
- `raw_integrity.json`：三份原始CSV标定前后SHA-256一致。

所有相关图统一使用中文标题、图例、坐标轴和中文字体；保留W、s、r/min等单位。历史一阶、事件模型、空载参考、灰箱和恢复候选五张图均已重绘，研究界面中的进给与功率分解图也使用中文。仅重绘而不重新标定可运行：

```powershell
python scripts/verification/render_base_power_figures.py '<空载CSV目录>'
```

重绘前后CSV、模型和数值报告的SHA-256检查记录于 `output/load_prediction/figure_localization_integrity.json`。

## 软件检查

新增9项恢复模型测试，覆盖合成数据、早期波形保持、曲线与特征一致、负功率、短尾段拒绝、右删失、保存加载、取消、未来数据隔离、文件/档位留出及原生Tk查询。Conda AFC全套回归已通过131项测试和65项子测试。

首次默认捕获输出的全套测试停在原有 `test_current_requirement.py` 的图表错误弹窗，已终止该次运行；改用 `-vv -s` 后整套通过。没有据此修改原图表业务逻辑或声称已解决其弹窗根因。详细日志为 `output/load_prediction/recovery_regression_verbose.log`；UTF-8、语法和新增文件空白另行检查。

中文绘图调整后再次运行全套回归：131项测试、65项子测试通过，用时30.03秒，日志为 `output/load_prediction/recovery_regression_chinese.log`。五张图均已检查中文字体与标注；中文重绘同时验证相对路径、绝对路径输入与原数据指纹一致。

计算核心在 `base_recovery.py`，比较编排在 `recovery_validation.py`；复用原读取、事件提取、参考校正和评分，遵循DRY。候选与界面、当前模型分开，遵循SOLID；限制为两种小规模尾段候选，不增加神经网络或GPR依赖，遵循KISS/YAGNI。

下一步优先增加独立的中高转速空载重复启动记录，记录真实S指令时刻、起始状态及停转间隔，并打乱转速试验顺序以区分转速效应与运行顺序效应。恢复时间接近阈值时还受平台漂移和纹波影响；目前证据不足以承诺仅换成GPR或更高阶系统就能达到0.5秒。
